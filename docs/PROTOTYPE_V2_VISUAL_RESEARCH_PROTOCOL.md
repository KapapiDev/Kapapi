# KAPAPI Prototype v2 — Visual Research Protocol

Status: **mandatory visual-research gate for `feat/prototype-v2`**  
Updated: **2026-09-02**

Visual quality is the highest-priority execution risk for Prototype v2. This protocol exists because reading design notes is not equivalent to looking at excellent websites.

## 0. Core rule

**Do not design from memory, summaries, screenshots alone, or prose-only reference notes. Open the live sites and look at them.**

For each reference, scroll through the full public landing/product experience where reachable. Inspect actual composition, transitions, motion, density, imagery, product framing, and mobile behavior.

## 1. Mandatory named references

Open and inspect the live sites already defined by canon/addenda:

Global/product quality:

- Upwork
- Linear
- Vercel
- Factory
- Raycast
- Hyperstudio
- Mercury

Korean marketplace/product conventions:

- Kmong
- Wishket
- Soomgo

Do not stop at the first viewport. For each reachable site:

- inspect hero,
- scroll through at least three meaningful mid-page sections,
- inspect footer/final CTA,
- trigger visible hover/scroll/motion interactions where practical,
- inspect at least one narrower/mobile viewport when tooling supports it.

Capture evidence, not only written notes.

## 2. Broad discovery beyond the named list

The named references are a starting set, not the ceiling.

Before choosing KAPAPI's visual direction, conduct a **broad current survey of high-quality SaaS, marketplace, AI/productivity, fintech, developer-tool, and premium B2B websites**.

Use live web search plus high-quality design/reference discovery sources where reachable, such as:

- Refero
- SaaSFrame
- Godly
- Land-book
- Awwwards
- Lapa Ninja
- One Page Love
- curated contemporary product/landing galleries available in the environment

Discovery requirement:

- build a pool of **at least 30 current candidate websites** beyond the mandatory list,
- quickly visually screen the pool,
- choose at least **12 additional sites** for deeper live inspection,
- include only sites whose current visual quality materially teaches something useful to KAPAPI.

Possible quality families to search around include companies/products such as Stripe, Ramp, Attio, Notion, Framer, Webflow, Clerk, Arc, Contra, Deel, Pitch, Retool and other current high-polish products, but do not treat this list as fixed. Find the best current examples yourself.

## 3. Skill/plugin/tool use is mandatory

Before research, inventory all installed capabilities related to:

- UI/UX design,
- frontend design,
- web design,
- Korean UX writing/copy,
- visual critique,
- browser/computer use,
- screenshot capture,
- responsive testing,
- animation/motion,
- design-system analysis,
- image/video compositing.

Actually invoke relevant tools/skills/plugins.

If `ui-ux-pro-max` or an equivalent design skill is available, use it.

If a Korean-language/UX-writing skill is installed, use it during copy review.

Do not write “not available” until an actual discovery/call attempt has been made.

## 4. What to inspect visually

For every deep reference, record with screenshots/visual evidence where possible:

- hero height and crop,
- headline scale and line breaks,
- typography family/weight contrast,
- grid width and column behavior,
- whitespace rhythm,
- navigation height/density,
- primary CTA treatment,
- image/video scale and integration,
- product UI framing,
- how visuals replace explanatory prose,
- section transitions,
- light/dark sequencing,
- color/accent restraint,
- border/radius/shadow behavior,
- motion timing and purpose,
- scroll choreography,
- card density or deliberate lack of cards,
- trust proof placement,
- final CTA/footer treatment,
- mobile adaptation,
- what feels expensive/premium,
- what feels generic/templated.

## 5. Side-by-side comparison requirement

Do not merely write separate notes for each site.

Create comparative visual boards/contact sheets or equivalent side-by-side evidence for:

1. hero composition,
2. product/media integration,
3. mid-page storytelling,
4. marketplace/trust patterns,
5. Korean copy/CTA patterns,
6. mobile first-view behavior.

KAPAPI visual directions must be reviewed beside these references, not judged in isolation.

## 6. Visual-first implementation gate

No final application implementation may begin until:

- live reference research is complete,
- broad discovery pool is complete,
- deep-inspection shortlist is complete,
- actual visual evidence exists,
- three KAPAPI visual directions are rendered and inspectable,
- at least one direction survives side-by-side comparison with the strongest references.

Do not substitute prose mockups for visual directions.

## 7. Visual communication priority

The landing must **show before it explains**.

Avoid sections whose primary content is:

- long Korean paragraphs,
- numbered text columns,
- strategy-document prose,
- feature descriptions that should have been product visuals,
- a wall of cards with explanatory text.

Prefer:

- live product UI,
- actual interaction states,
- motion/state changes,
- media,
- object transformation,
- real marketplace examples,
- trust numbers,
- concise labels,
- visual comparison,
- spatial hierarchy.

A public landing page is not a specification document.

## 8. Rendered-app loop

After each major section is implemented:

1. open the rendered site in a browser,
2. scroll through it at normal viewing speed,
3. capture the section,
4. compare it beside the strongest relevant references,
5. ask whether the same idea is being communicated visually or being explained in text,
6. redesign if it looks like generic SaaS/B2B documentation,
7. repeat before continuing.

Do not wait until the end to discover that the entire page is visually weak.

## 9. Final visual acceptance

Prototype v2 is not ready merely because product behavior is correct.

The first and mid-page experience must survive side-by-side comparison with the reference set in:

- visual confidence,
- composition,
- polish,
- motion,
- media integration,
- Korean-market familiarity,
- KAPAPI distinctiveness.

If the primary defense of a section is “the copy explains it clearly,” the section is not visually finished.
